# Website plan

The EnvoScale website explains the project in a minute, lets people try Envol, holds the
documentation, and sells commercial licenses. **It is written in Envol**, with `envoweb`
and the Envor templates, so it is built when that stack exists (M9), not before: the
site is itself a demonstration that EnvoScale can build a website. Each phase is an issue
under the **Website** epic on the [roadmap](https://github.com/orgs/envoscale/projects/3).

## Goals

1. **Understand it in 60 seconds.** What EnvoScale is, the Hello World Gallery, and why
   one language for every layer matters (brief §1, §3.2).
2. **Try it without installing.** The sandbox runs Envol in the browser.
3. **Learn it.** The learning path from `docs/guides/` and the language specification.
4. **Buy it.** Enterprise pages: what the commercial license covers, editions and prices
   once set ([#36](https://github.com/envoscale/EnvoScale/issues/36)), support,
   security, and how to get an evaluation license.
5. **Trust it.** Status, roadmap, reproducible builds, security policy.

## Rules

- **Written in Envol.** Pages, components and the sandbox are Envol code in this folder,
  built by `envo build`. The HTML, CSS and the small JavaScript loader are generated by
  EnvoScale (brief §9.4). No hand-written web stack and no third-party code: no
  frameworks, CDNs, web fonts, analytics or trackers.
- **No cookies,** so no consent banner.
- **Accessible:** WCAG 2.2 AA (brief §9.2), keyboard navigable, respects reduced motion
  and light/dark settings.
- **Envor design** (brief §9.1–9.2): "clean, calm, translucent, softly animated", with the
  logo's black and blue as the accent.
- **Static first:** the site is generated ahead of time (SSG); only the sandbox needs
  WebAssembly.

## Phases

### Phase 1: the site in Envol (M9)

The brief's M9 definition of done includes "The EnvoScale docs site is built with
EnvoScale." This phase is that site: every page in the site map except the live sandbox,
built from Envol with the Envor Landing and Docs templates, with the docs pages generated
from `docs/`. It is also the first large `envoweb` program, so the problems it finds are
fixed in `envoweb` and Envor, not worked around in the site.

### Phase 2: public launch (owner decisions)

Needs the owner's go-ahead because it publishes and may cost money: a domain, hosting
(GitHub Pages from a public `envoscale/website` repository is free and needs no server),
and the go-live date.

### Phase 3: the sandbox

Envol runs in the browser with no server, so nothing users type leaves their machine and
there is no server to secure or pay for.

- **3a.** The EIR interpreter (M6), compiled to WebAssembly by the WASM backend (M9),
  runs sandbox programs with no file or network access.
- **3b.** The compiler itself, compiled to WebAssembly, compiles sandbox programs in the
  page so they run at near-native speed.
- Share links encode the program in the URL fragment, so nothing is stored.

State (M13): 3b is live in `build/site/sandbox/` with share links (`#code=`, base64url of
the program's UTF-8); it covers 3a's aims (no server, no file or network access), so the
EIR interpreter is not needed in the page.

### Phase 4: enterprise portal

After editions and prices are set (#36): pricing, the support policy, security
advisories, and a trust page covering reproducible builds, SBOMs, signed releases and LTS
schedules. Licenses are still sold by signed Order Form; the portal is information and
contact, not checkout.

## Organization profile README (now)

Unlike the website, the public profile at [github.com/envoscale](https://github.com/envoscale)
(`envoscale/.github`, `profile/README.md`) is plain Markdown and is live. It
carries the home page's message with self-contained animated SVGs (CSS
animation only, no scripts or external services, reduced-motion aware):

- a terminal typing `envoc0 build hello.envol` and running the result;
- the bootstrap ladder: hex seed → Stage 0 → Stage 1 → Stage 2 → fixed point (A == B);
- the compiler pipeline: source → tokens → syntax tree → EIR → x86-64 → PE and ELF;
- the Hello World Gallery cycling through its programs;
- a progress strip of the milestones.

It is refreshed at each milestone: the SVGs are plain text in `profile/assets/`, so updating
a number or a milestone state is an edit to the SVG.
